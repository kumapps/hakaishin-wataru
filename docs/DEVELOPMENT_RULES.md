# GitHub開発管理ルール v1.0

制定日：2026-11-08／方針追記：2026-11-08（Asia/Shanghai）。ゲーム版はv0.9.36を維持。

## 正本・決定権・担当

- `kumapps/hakaishin-wataru` のGitHub上の仕様書・ソースコードを唯一の正本とする。チャット、添付ZIP、ローカルの複製は検討資料とし、決定と変更をリポジトリへ記録する。
- 仕様の最終決定権はユーザーにある。ChatGPTは主に企画・仕様検討、Codexは主に技術調査・実装・テストを担当する。提案を確定仕様として扱わない。
- ゲーム仕様の担当分担・適用順は [MASTER.txt](MASTER.txt) と各テーマの既存仕様に従う。ユーザーの新指示と既存仕様が矛盾する場合は、変更前に内容と影響を報告し、解消まで該当変更を進めない。

## 未確定仕様・過去資料の扱い（2026-11-08決定）

- 未確定仕様は原則ChatGPTのチャット内で検討し、ユーザーが確定した段階でGitHubの担当仕様書へ登録する。検討案・途中の試作品を正式仕様と混同しない。GitHubを正本とする対象は確定仕様・管理方針・登録済みソースであり、チャットでの検討を妨げない。
- 戦闘画面の新UIとキャラクターアニメーションは現在も検討中。本体への実装指示ではない。既存文書の採用記録は当時の記録として保持し、新仕様や本体接続の承認へ拡大しない。
- 漢字リズムゲームは別プロジェクトであり、本リポジトリに仕様・ソース・開発予定を登録しない。
- 過去のアーカイブ・QA資料は一括回収せず、今後の開発・検証で必要な場合に限って回収する。未収録資料の参照には「未収録・所在不明・必要時確認」等の状態を示す。不足資料は推測で再生成せず、過去の検証を再現済みと扱わない。
- 古い情報・リンク・適用版・更新状態は必要最小限で整理する。過去の確定仕様と検証履歴、元の制定日・検証日は保持し、管理上の追記日と区別する。整理によってゲームの動作・仕様を変更しない。

## 状態の記録

| 状態 | 意味・必要な根拠 |
|---|---|
| 検討中 | 提案・調査中で、ユーザーの仕様確定前。原則チャット内で扱い、GitHubでは必要な状態注記にとどめる |
| 確定・未実装 | ユーザー決定済みで、対象コード・文書への反映前 |
| 実装済み・未確認 | 反映済みだが、対象に必要な確認が残る。自動テスト成功だけで実機確認済みにしない |
| 確認済み | 対象・版・確認方法・結果を明示し、必要な確認が完了した範囲のみ |

実装状態と確認範囲を併記する。自動テスト／ブラウザ検証とユーザーの実機確認は、日付・対象版・環境・操作・結果・未確認範囲を分ける。過去の確認を新仕様や全端末の確認へ拡大しない。不明は不明とし、未確認事項を確認済みと記載しない。

## ブランチ・Pull Request

- `main` は安定版とする。通常の開発は最新の `main` から専用の作業ブランチを作成する。
- 変更は原則Pull Request（PR）で差分・仕様・検証結果を確認してから統合する。PRには目的、変更範囲、関連仕様・決定、検証結果、残課題を記載する。ユーザーがマージ待ちを指定した場合は承認までマージしない。
- 既存Git履歴の書き換え・強制pushは禁止する。公開済みの誤りは追加コミットで修正する。

## ディレクトリと公開

| 場所 | 役割 |
|---|---|
| `docs/` | 仕様・管理ルール・決定・進捗・変更履歴の正本 |
| `game-source/` | ゲーム本体の編集用ソース |
| `prototype/` | 独立した試作品。採用・本体への組込み・公開承認を区別する |
| `playable/` | 公開用ファイル。ユーザーの明示的な公開承認がある場合のみ更新する |
| `migration-notes/` | 移行時点の資料・検証記録。現行状態との相違は担当仕様・ROADMAPで判断する |

本体の実装依頼や試作品の採用だけを公開承認と解釈しない。公開対象・版・範囲の明示承認後にのみ公開版へ反映する。公開URLや配信設定の変更も明示承認を要する。

## 仕様と記録の更新

- 仕様変更は対応する既存テーマ仕様書へ反映する。同じ仕様の正本を複数作らず、他の文書には参照を残す。
- 重要な決定は [DECISIONS.md](DECISIONS.md)、開発進捗・現在の状態は [ROADMAP.md](ROADMAP.md)、実施済み変更は [CHANGELOG.md](CHANGELOG.md) に記録する。過去の変更履歴は当時の記録として保持する。
- 決定記録は日付・対象機能・決定内容・理由・関連仕様書・実装状態を残す。既存仕様の大量転記を避ける。新決定で更新する際は旧決定との関係を記録する。
- 文書版・ゲーム版は別管理とする。管理文書だけの変更でゲーム版を上げたりPlayableを再生成したりしない。
- 公開版更新時は対象コミット、ゲームのバージョン、検証・実機確認の範囲を記録し、対応する `vX.Y.Z` のGitタグを付ける。既存タグは移動・上書きせず、過去版へ推測でタグを付けない。

## 実装・検証・保護

- 確定仕様に反する変更を独断で実施しない。変更対象外の機能・素材・設定を維持する。既存難易度、手書き認識基準、セーブデータ互換性を理由なく変更しない。変更が必要なら根拠・影響を示し、仕様決定を先に得る。
- 実装後は変更に応じた必要なテストを実施し、成功・失敗・未実施とその理由を記録する。保存互換性や認識・難易度に関係する場合は対応する回帰確認を行う。
- [AGENTS.md](../AGENTS.md) のGit Author・Committer設定と個人情報保護ルールを維持し、作業開始時とコミット前に確認する。
- 個人情報・個人メール・認証情報をコミットしない。秘密値は安全な環境設定で管理する。ライブラリの作者表記・著作権・ライセンス・出典は保持し、第三者素材やモデルの利用・再配布条件を確認する。検出文字列は文脈を調べ、秘密情報か作者情報かを区別する。新たに疑わしい情報を見つけたら公開前に報告する。
