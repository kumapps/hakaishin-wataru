## 1. 文書の役割

手書き認識の採用方針、認識器の基準版、設定、検証範囲、既知の制約、調整手順の正本を本書に分離する。ゲーム全体と戦闘仕様には要約と参照を残す。

本書は完成した一文字の認識を対象とする。1画ずつ進むなぞりガイド、回答タイマー、ATB、死亡中断、学習記録の確定、魔法の効果計算はゲーム正本の規則に従う。手書き認識に関する旧試作の説明と矛盾する場合は、今回の採用方針と本書を優先する。過去版は比較・再現用の履歴として残す。

採用基準版が決まったことと、ゲーム本体へ実装済みであることを区別する。**v0.9.26へ統合済み。自動／Chromium検証と、ユーザーの実機確認を区別する。**

## 2. 学習上の目的と正誤

- 子どもが指やペンで普通に書いた、漢字として成立している字を正解にする。美しい字や教材と同じ筆跡は要求しない。
- AI認識を基本に採用する。お手本の全筆画について位置・長さの一致率を要求する方式には戻さない。
- 線の位置・長さ・傾き・はね方の自然な違い、大きさや入力欄内の位置の違いを許容する。
- 書き順・筆画方向・指やペンを離す回数・線の区切りの違いだけを理由に不正解にしない。線をつないだ結果、字形自体が変わった場合は別途判断する。
- 書き順ボーナスは字形の正誤と分離する。形が正しくても区切りや書き順を確認できなければ、正解・ボーナスなしとする。入力ストローク数の一致だけでボーナスを付けない。
- 補助チェックは、明らかな重要線の抜け・別の字になる構造違いを止めるために使う。検出が曖昧なことを学習者の誤りと断定しない。

## 3. 候補集合：漢字の書の登録済み漢字

1. 認識候補は、ゲームの「漢字の書」に登録済みの漢字一覧から選ぶ。
2. 小学生漢字全体やモデル内の漢字全体を、そのまま候補集合にしない。登録状態はゲーム側の正式データから受け取る。
3. カタカナ・ひらがな・未登録漢字は最終候補から除外する。「木」をAIが「ホ」と強く見た場合も、登録済み漢字の候補として木を検討できる。
4. 出題の正解字だけに絞らない。登録済み漢字すべてを競合させ、別の登録済み字への書き間違いも判別する。期待する答えは、候補を選んだ後に一致を確認するため別入力とする。
5. 元の上位5件だけから選別せず、全クラスのスコアから登録済み漢字を探す。上位5件より下にある候補も検討対象にできる。
6. 候補集合を狭めた結果の相対スコアだけで正解にしない。元の認識の根拠、登録済み候補同士の競合、強い対象外漢字の認識を確認し、根拠が弱い場合は保留する。
7. 出題字が登録済み一覧にない場合、認識器が正解字を自動追加して救済しない。統合上の候補資格・出題データの整合を確認する。例外は初回札の代表字なぞりのみで、その場だけ代表1字を候補へ追加する。全字登録はスキップ／正解による終了時。通常出題・任意練習・魔法・封印解除では期待字を自動追加しない。

同形のカナと漢字は画像だけで書き手の意図を区別できない。候補限定は登録済み漢字の文脈を使う設計であり、カナを漢字へ変換しただけで必ず正解になる仕組みではない。

## 4. 基準実装v0.4

### 4.1 判定の順序

AIで一文字の全クラススコアを得る → 登録済み漢字を抽出・順位付け → 根拠と競合を確認 → 期待字と比較 → 対象字の構造補助 → 学習判定。書き順ボーナスは別処理。

AIの元スコアと、登録済み候補内で正規化した相対スコアを区別する。表示される％を実際の正答率と扱わない。

### 4.2 現在の候補選択設定

| 設定 | v0.4の値 | 用途 |
|---|---:|---|
| minimumRawScore | 0.10 | 選んだ登録済み候補に元の認識の根拠があるか |
| minimumScopedScore | 0.70 | 登録済み候補内の第一候補の相対スコア |
| minimumScopedMargin | 0.20 | 登録済み内の第一・第二候補の差 |
| unregisteredKanjiVetoScore | 0.70 | 全体第一候補が未登録漢字で、この元スコア以上なら保留 |

`src/registered-candidates.js` の `REGISTERED_CONFIG` に集約。v0.4基準値として維持し、統計的に校正済みの値とはしない。実例に基づく必要がある場合だけ、設定版と比較結果を残して調整する。

例：ホ0.60・木0.35・本0.05で木と本が登録済みなら木を選べる。一方、ホ0.99・木0.01では木の元の根拠が弱いため保留。王0.85・玉0.15で玉だけ登録済みでも、王の強い認識を無視して玉を正解にしない。

### 4.3 構造補助の対応範囲

| 字 | 確認する重要な要素 |
|---|---|
| 玉 | 横線の構造と、その間の右側に点の証拠があるか |
| 本 | 中央を横切る下側の短い横線があるか |
| 末・未 | 上部2本の横線の長さの関係が逆転していないか |

完成した字形をラスター化して確認し、筆画の区切り・順番に依存させない。末／未の上／下横線の長さ比は、1.20超なら末、1/1.20未満なら未、それらの間は曖昧として保留する。

この補助はv0.3から変更しない。月を含む他の字には専用の線抜けチェックがなく、AIが欠けた字を補完して読めば通る可能性がある。「重要な線抜けを全漢字で防止済み」と扱わない。

### 4.4 結果の区別

認識結果の種類を内部で区別する。正解以外の別字・構造不一致・曖昧／保留・空入力は通常の誤答規則へ接続する。出題字が正式候補にない場合や、モデル取得・実行等の処理エラーは学習者の誤答にせず、同じ問題・筆跡・成功数・残り時間を保持して再試行できる。学習記録を増やさない。判定待ちの問題タイマーは停止、戦闘ATBは既存ON／OFF設定を守る。死亡・取消・終了後の古い結果は無効、非表示／一時停止中は結果確定を待つ。

## 5. 技術基準と成果物

- AI：LT8 / japanese-handwriting-onnx。固定リビジョン `7e4fa1096b1fd4dc1afb9f8ffc5b9d936adb2839`、`model.fp16.onnx`、3,082クラス。
- ランタイム：ONNX Runtime Web 1.20.1、WASM、numThreads=1、proxy=false。
- AI画像前処理：512×512入力、線幅14px、白背景、補助線なし、128×128の0〜255グレースケール。前処理版 `v0.2-512px-14px-128gray`。
- WASMモジュールとバイナリの両方に絶対Blob URLを指定する修正を維持する。
- 認識は端末内で実行。モデル初回取得時等を除き、手書き画像・軌跡を外部へ送らない。モデルファイル指定・利用可能な場合のキャッシュを維持する。
- 検証HTML：`kanji_ai_handwriting_test_v0_4.html`。
- 編集元・設定・テスト・出典：`kanji_handwriting_source_v0_4_2026-10-14.zip`。モデル重みは同梱しない。
- 開発履歴：`kanji_handwriting_handover_v1_0_2026-10-12.md`。ファイル名は旧版名だが本文の資料版を参照する。

独立検証画面の71字は仮登録であり、ゲームの登録状態ではない。モデルの認識クラス数、出題データの字数、なぞり素材の整備数、実際に評価した字数を混同しない。

## 7. 実例保存と版管理

- 新しい検証結果は `kanji-ai-test-v3`。アプリ版・前処理版・モデル・登録済み一覧・全AIスコア・無制限候補・限定候補・各判定・軌跡・端末情報・入力方法・人の正誤ラベル・誤り種類・メモを保存する。
- 人のラベルは正しい／誤り／曖昧／未評価を区別し、判定結果に合わせて付け替えない。正しい字の誤拒否と誤字の誤受入の両方を確認する。
- 検証画面は最大100件を開いている間だけ保持。閉じる前にJSON保存。自動で実例が永続蓄積されるとは扱わない。
- v0.4記録は保存全スコアと当時の登録条件で補助判定を再比較できる。これは実AIの再実行とは別。軌跡を開いて認識を押すと実AIで新記録を作る。
- v0.2/v0.3の旧JSONには全スコアがないため、候補限定の確定比較は行わない。保留としてv0.4の比較集計から除外し、必要なら実AIで再認識する。
- 設定・調整版・検証結果・既知の未対応をテーマ単位で更新する。旧版HTML・ソース・実例を消して再現性を失わない。調整に使った例と未見の例を区別する。
- 子どもの氏名等は収集不要。外部の学習サービスへ実例を自動送信しない。
